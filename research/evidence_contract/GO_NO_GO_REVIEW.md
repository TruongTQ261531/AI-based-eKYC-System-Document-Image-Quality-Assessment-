## Why the current design is insufficient

1. **Representation is not a new oracle capability.** Flat availability/typed references plus the same simple preconditions reproduce A on every primary output. The graph adapter still organizes annotation, but explicit graph data structure is not an experimentally demonstrated detection innovation.
2. **The strongest baselines were intentionally kept capable.** B3/V3 score the same visible field errors; generic source-blind mutation rules are weaker because their expectations omit available-source facts. Superiority only over B2 would not satisfy the frozen research-gap claim.
3. **Original correctness is the main bottleneck.** A excludes20/60 and22/60 packs from a regression relation. C2 never obtains a successful correct backup reading on this selected authored panel. This could reflect source/layout/OCR/rectification/parser difficulties; the present trace and missing independent semantic/readability audit cannot assign a confirmed cause. Do not fix or tune historical readers to manufacture a better testing result.
4. **No fault study exists yet.** These are single-version neural behaviors on5 authored physical IDs, not a controlled/historical software-fault pool. Without independent reference validity and patch/revert/activation provenance, unique defect recall, real false alarms and root-cause yield cannot be estimated.
5. **Generation comparison is narrow.** Both selectors receive the same already-valid finite pool; primary yield is63/63 for both. This isolates ranking, not online generation efficiency. Only2 correlated seed runs, within-bin area differences and16 vs17 distinct primary rasters remain. More correlated images cannot remedy missing verification or create statistical power over root causes.

## Proposed bounded next work, not executed here

Keep current results as negative/exploratory evidence. Before any further model runs:

1. Audit a small balanced reference pool independently of the generator and SUT: complete/incomplete source coverage, backup precision/checksums, shared semantic context, partial glyph removal and both valid/invalid relations. Include positives and negatives; do not select only cases where A wins or the model reads the original correctly. Construction support and human readability must remain separate.
2. Compare A primarily against **frozen V3+the same validity gate** and the flat conditional checker. Determine exactly what information/precondition, if any, adds verified error-diagnosis or reduces triage effort. An equally capable baseline is a possible final finding, not a reason to weaken it.
3. Curate genuinely reproducible historical pipeline faults or an explicitly separated controlled-fault pool across geometry/reader/parser stages, with patch/revert or activation artifacts and four-output version witnesses. Do not count oracle unit injections as real faults or invent histories to meet a sample-size target.
4. Measure annotation/review/setup cost, including rejected proposals, and prespecify cache/duplicate-normalized budget prefixes before considering a larger matched-budget study. Report cold-start and amortized costs. More seeds/models are not the immediate priority.

If an independently audited pool still yields the same decisions for A and the simple conditional checker, narrow the prospective paper framing to an **empirical study of oracle validity and failure triage in document pipelines**, with taxonomy/reference artifacts as the contribution. That would require a separately approved/prospective protocol update and adequate evidence; it is not an automatic change to the present RQs or a claim of algorithmic novelty.

The external implementation eligibility assessment is in [BASELINE_PROTOCOL](BASELINE_PROTOCOL.md): the runnable frozen V3 code was included; GenMorph/VeriOCRBench/LLMorph were inspected as primary-source implementation references, not executed as equivalent baselines or credited with borrowed results. Deployment/UI features, model fine-tuning and checkpoint size are outside this Go/No-Go decision.
